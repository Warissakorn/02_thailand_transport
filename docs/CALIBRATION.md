# ผลการ Calibration — ตรงไปตรงมา

## เกณฑ์ที่ใช้ — และข้อผิดพลาดที่พบเมื่อ 18 ส.ค. 2569

โปรเจกต์นี้ตั้งเกณฑ์ไว้ว่า **GEH < 5 ที่ 85% ของสถานี** (`geh_target` / `geh_pass_pct`)
แล้ววัดจาก **AADT รายวัน** ตรง ๆ — ซึ่งผิดหลักการวัด:

> GEH นิยามไว้กับ **ปริมาณรายชั่วโมง** และ *ไม่ใช้กับปริมาณรายวันหรือค่ารวมช่วงเวลา*
> (ATAP §5 Model development, Appendix C ; UK DfT TAG Unit M3.1 ใช้กับ hourly link flows)

เพราะ GEH เติบโตตาม √(ปริมาณ) การเอาไปใช้กับค่ารายวันจึงขยายค่าขึ้นเองราว
`√(1/K) ≈ 3.3 เท่า` (K = 0.09) เกณฑ์ "GEH<5 บนรายวัน" จึงเทียบเท่ากับการเรียกร้อง
**GEH < 1.5 บนชั่วโมงเร่งด่วน** ซึ่งเข้มกว่ามาตรฐานสากลอย่างมาก และไม่มีแบบจำลองใดผ่าน

**เกณฑ์ที่ใช้ตั้งแต่บัดนี้** (ขั้น 14 รายงานให้ครบทั้งสามชุด):

| ตัวชี้วัด | หน่วยที่ถูกต้อง | เกณฑ์อ้างอิง |
|---|---|---|
| GEH < 5 | **ชั่วโมงเร่งด่วน** (AADT × K) | TAG M3.1: >85% ของ count |
| ค่าต่างรายเส้น | ชั่วโมงเร่งด่วน | TAG M3.1: <700 veh/h → ต่างได้ 100 veh/h · 700–2,700 → 15% · >2,700 → 400 veh/h (>85% ของกรณี) |
| %RMSE แยกกลุ่มปริมาณ | **รายวัน** | แนวปฏิบัติ FHWA/state DOT สำหรับโมเดลระดับภูมิภาค-ประเทศ |
| screenline | รายวันหรือชั่วโมง | ±5–10% (TAG / ATAP) |

ATAP ระบุไว้ด้วยว่าเกณฑ์ควร **ตกลงกันก่อนเริ่ม validate ให้เหมาะกับขนาดและวัตถุประสงค์
ของแบบจำลอง** เช่น GEH<5 ที่ 90% ของ count ในพื้นที่โครงการ แต่ 75% นอกพื้นที่ —
ไม่ใช่ตัวเลขเดียวใช้กับทุกแบบจำลอง

**สิ่งที่ยังไม่เปลี่ยน**: การเปลี่ยนหน่วยวัดไม่ได้ทำให้แบบจำลองแม่นขึ้น มันแค่ทำให้
ตัวเลขที่รายงานเทียบกับมาตรฐานได้จริง ผลรอบ 18 ส.ค. 2569 (medGEH รายวัน 65.4)
เทียบเท่า medGEH ชั่วโมงเร่งด่วนราว 19.6 ซึ่ง **ยังไม่ผ่าน** เกณฑ์ GEH<5 อยู่ดี

รวม access/egress (รถ/บรรทุกเข้า-ออก terminal) เข้า road assignment แล้ว — **อำเภอยังดีสุด**
(เพิ่ม access/egress ไม่เปลี่ยน GEH มาก เพราะเป็นส่วนเสริมเล็กเทียบ door-to-door)

**ข้อค้นพบ:**
- Equilibrium กระจายจราจรได้จริง (max flow ลดเกือบ 3 เท่า) แต่ GEH ไม่ขยับมาก
- **โซนอำเภอ + beta เหมาะสม = ดีที่สุด** — R² −0.13→≈0 (จากสวนทางเป็นกลางๆ), median GEH 83→64
- โซนละเอียด+distribution ช่วยจริง **แต่ยังไม่พอผ่าน** (เป้า 85%) ต้องทำครบ: equilibrium-อำเภอ + calibrate trip-rate + **พิกัด AADT แม่นจริง** (ตอนนี้ geolocate แบบประมาณ → snap noisy)

> ⚠️ พบและแก้ **bug สำคัญ**: กราฟ feature-level เดิมเชื่อมแค่ปลายเส้น (พลาด T-junction) แตก 24,642 ชิ้น ใหญ่สุด 48% → แก้ด้วย proper noding (split ที่จุดตัด) เชื่อม 95.7% กระทบ province-equilibrium เดิมด้วย (ควร re-run ด้วยกราฟใหม่)

## สาเหตุหลัก (ทำไมไม่ผ่าน — สำคัญ)
1. **All-or-nothing assignment** — ทุกการเดินทางวิ่งเส้นสั้นสุดเส้นเดียว ปริมาณกระจุกบน corridor เดียว เป็น 0 บนเส้นขนาน ขณะที่จราจรจริงกระจายหลายเส้น (ไม่มี congestion/route choice) → ต้นเหตุหลัก
2. **โซนระดับจังหวัด (77) หยาบเกินไป** — แต่ละจังหวัด = 1 centroid การเดินทางภายในจังหวัด (intrazonal ~13-40%) ไม่ลงถนนระหว่าง centroid เลย แต่ AADT จริงส่วนใหญ่คือจราจรท้องถิ่น/ระยะสั้น → โมเดลมองไม่เห็น
3. **ขนาด trip generation ยังไม่ calibrate** (2 เที่ยว/คน/วัน เป็นค่าตั้งต้น)
4. geolocate AADT เป็นการประมาณ (วางตามสัดส่วน กม. ในจังหวัด) อาจ snap ผิดเส้นขนาน

## สิ่งที่โมเดลทำได้ดี
- **รูปแบบ corridor สัมพัทธ์** (เส้นไหนหนาแน่นกว่ากัน) ถูกต้อง — กรุงเทพ-radial, EEC, คาบสมุทรใต้
- กรอบ multimodal + 4-step ครบ, pipeline ทำซ้ำได้ทั้งหมด

## เพื่อให้แม่นระดับ link (ผ่าน GEH) ต้องยกระดับ
| ปรับปรุง | ผลคาดหวัง |
|----------|-----------|
| **Equilibrium assignment** (capacity-constrained, เช่น BPR + Frank-Wolfe) | จราจรกระจายหลายเส้นตามความจุ — แก้สาเหตุ #1 |
| **โซนละเอียดขึ้น** (อำเภอ 928 / ตำบล 5,926) | จับจราจรท้องถิ่น — แก้สาเหตุ #2 |
| **เพิ่ม intrazonal/local road loading** | AADT บนถนนรองสมจริง |
| **calibrate trip rate + beta + logit** กับ AADT ซ้ำ | สเกล + สัดส่วนตรงขึ้น |

> สรุป: โมเดล v1 ใช้วางแผนเชิงยุทธศาสตร์/ดูภาพรวม corridor ได้ แต่ยังพยากรณ์ปริมาณราย link ไม่แม่น ต้องทำ equilibrium assignment + zone ละเอียดก่อน
